# Family Budget Pipeline

A data engineering portfolio project that transforms synthetic household banking transactions into reliable financial reports.

## Goal

Build a reliable data pipeline that loads bank CSV exports in small, repeatable batches without creating duplicate transactions.

The long-term goal is to validate data quality, organize cleaned transactions into a star schema, and visualize household spending, income, and cash flow in Power BI.

## Pipeline Architecture

**Current implementation:**

CSV Files → Python → SQLite Database

**Planned architecture:**

CSV Files → Python Ingestion → Data Quality Checks → SQL Star Schema → Power BI Dashboard

## Project Structure

- `src/` — Python ingestion and transformation scripts
- `docs/` — Architecture documentation, design notes, and data dictionary
- `data/sample/` — Fictional banking transactions used for testing
- `data/budget.db` — Local SQLite database generated by the ingestion script (excluded from Git)

## How to Run

### Requirements

- Python 3
- SQLite (included with Python's standard library)
- Git (for cloning the repository)

### Instructions

1. Clone the repository:

   `git clone https://github.com/JeromyO/family-budget-pipeline.git`

2. Navigate into the project directory:

   `cd family-budget-pipeline`

3. Run the Python ingestion script:

   `python3 src/load_transactions.py`

### Expected Output

`Total transactions in database: 5`

The script creates a SQLite database at `data/budget.db` and loads five synthetic transactions.

## Duplicate Prevention

The pipeline uses two SQLite features to prevent duplicate transaction IDs:

- **PRIMARY KEY:** Enforces uniqueness on the `transaction_id` column.
- **INSERT OR IGNORE:** Skips records that violate the primary key constraint rather than inserting duplicates.

Running the script multiple times with the same sample CSV will maintain five transactions in the database.

This demonstrates **idempotent ingestion**, an important concept in data engineering.

## Privacy and Security

This public repository contains synthetic financial data only.

Real financial exports, account numbers, credentials, and other sensitive information must never be committed.

The `.gitignore` file excludes local SQLite databases, raw banking exports, environment files, and Python-generated files.
